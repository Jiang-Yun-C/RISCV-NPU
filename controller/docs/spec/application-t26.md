# T26 外设接入合同（准备阶段）

T26 当前为 **ACTIVE**。本合同登记已有可复用组件和后续集成边界；尚无指定的实际传感器、外设接线或应用输出负载。配置见 [t26-application.json](../../configs/t26-application.json)，当前结果见 [应用板端报告](../reports/application-board-v1.md)。

继承 [T20 语义与执行合同](application-t20.md)及 [T25 已验收 SD 模型](../../versions/board-llm-v1.json)。模型负责中文到受限程序的生成，CPU 检查完整程序并暂存动作；拒绝、非法 JSON、非法设备和越界值不得产生输出写入。T20 的桌面模型意图回放不能作为 T26 的板端推理成绩。

## 可复用 I²C 组件

[i2c.h](../../firmware/application/i2c.h) 和 [i2c.c](../../firmware/application/i2c.c)提供单控制器、非保留 7 位地址的写、读及写后重复 START 读。协议依据 [NXP UM10204 Rev.7.0](https://www.nxp.com/docs/en/user-guide/UM10204.pdf) 的 START/STOP、ACK、clock stretching 和 bus clear 定义。设备是否采用 I²C，仍需实际型号确定。

`release(context, mask)` 的 bit0/bit1 分别为 SCL/SDA，1 表示高阻释放，0 表示拉低。平台实现必须读取实际同步后的 pad 输入；不能回读输出锁存器冒充外设响应。`delay_us` 由平台按实际时钟实现最小延迟。半周期至少 5µs；拉伸等待有独立、非零的微秒上限。实际总线频率、电压、上拉和波形仍须实测。

每方向最多 256 bytes，无堆分配。最后一个接收字节发送 NACK；整笔读取和 STOP 均成功后才复制接收缓冲区。地址或数据 NACK、SCL 等待超时、SDA 卡低均返回明确错误并释放两线。写入设备的字节可能已被接收，不能宣称写事务可回滚。故障不自动重试；调用者先记录原始错误，再显式调用 `nx_i2c_recover`，最多九个清总线时钟及 STOP。SCL 持续卡低返回超时，不操作供电或复位引脚。

主机独立引脚模型测试与 RV32 编译仅证明该可移植组件。此组件尚未接入 T25 固件、MMIO、RTL、FDC 或板上引脚；未测多控制器仲裁、10 位地址或设备寄存器/单位转换。

## 采样与推理时间

T20 的 `APP_TTL_CYCLES=1000000` 在 T25 的 125MHz 时钟下只有 8ms；32 位 mcycle 约 34.36s 回绕。T25 已测首 token 101.765s、32 输出请求 1195.958s。直接沿用 T20 的旧快照与低 32 位时间差，不能证明板端推理结束时的读数有效。

设备适配必须定义采样周期、量化/舍入、单位、有效范围、最大年龄以及失联/过时策略，使用可信采集端的版本和 64 位单调时间。若只接一个传感器，不得为另一个输入填充虚拟“有效读数”。动作前须按明确策略检查新鲜度及状态变化；不能通过无条件更新时间戳或放宽 TTL 掩盖旧样本。具体策略在设备确定后实现并测试，当前未实现。

## 板端集成待验

实际板最新报告为 V1.4，旧合同保留的 V1.2 核心/底板字段已被后续修正取代。逐项登记 FPGA ball → FMC pin → 子卡/header pin → 设备信号、方向、电压和上拉；保留 C24/B24 UART、A20 INIT 观测及现有 SD 占用。板载 EEPROM 地址响应不作为真实传感器验收。

设备确定后，实际模型原始输出、token/停止原因、CPU 检查、采样原始字节/转换值、版本/时间、实际 GPIO/PWM 动作和执行结果须关联同一请求。新增 SoC/引脚/探针需要独立 PDS2024 实现、时序及受影响 DDR 验收；还须补实际设备协议的 VCS/cocotb、同请求不同真实状态、失联/NACK/超时/过时/非法设备/越界和下一请求恢复证据。
