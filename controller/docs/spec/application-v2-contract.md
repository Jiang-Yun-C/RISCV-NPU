# T02 应用协议 v2：模型编译，确定性执行

此版本修复原始 T02 的混合职责问题，是用户要求“解决 blocked”后的明确方案变更。旧 `application-contract.md`、旧模型、数据和 FAIL 证据保持冻结；本版本不是对原始官方权重成绩的重新解释。

## 职责和模型身份

完整 Qwen2.5-0.5B 负责把中文编译成受限 JSON 程序。它不依靠正则表达式、样例 ID、预期标签、查表答案或按测试类别选择提示来生成程序。运行时只将请求文字、状态快照和固定协议放入模型 prompt；目标程序仅在独立训练阶段作为标签使用。

执行器只解释模型已经产生的程序，不读取中文指令。它验证完整程序，再执行数值比较、读取当前传感器值、选择条件分支、按顺序收集动作；任何非法字段、设备、数值或拒绝节点都会让整条程序不产生动作。它不纠正模型选错设备、漏指令或理解错误；这些由严格评分判失败。

若训练产生适配权重，发布物明确为官方固定 base＋应用 LoRA 合并后的 FP32 模型，不能称作未修改的官方模型。合并运算为 `W + (alpha/r) B A`，参数数目和推理网络结构保持 494,032,768 参数的原始 0.5B 规模。LoRA 使用本地 PyTorch 实现，独立单元测试验证零适配恒等与合并前后线性层数值一致。方法依据 [Hugging Face LoRA 文档](https://huggingface.co/docs/peft/en/developer_guides/lora)。

## 程序格式

程序是按执行顺序排列的 JSON 数组。支持：

```json
[["led",1],["pwm",35],["read","temperature"],["read","light"]]
```

- `led` 参数为整数 0 或 1；`pwm` 为整数百分比 0–100。
- `read` 读取 temperature（摄氏度）或 light（勒克斯）。模型只选择查询对象，执行器返回本次快照值。
- `if` 节点固定为 `["if", sensor, comparator, threshold, then_program, else_program]`。比较符只允许 `>`、`<`、`>=`、`<=`；阈值必须是有限范围整数。缺省 else 用空数组。
- 不支持的设备/请求由模型生成 `[["reject","UNSUPPORTED"]]`；越界 PWM 保留原数值交给执行器返回 RANGE。格式失败返回 FORMAT，不能冒充正确拒绝。

例如 `[["if","temperature",">",30,[["pwm",75]],[["pwm",0]]]]` 是模型对条件指令的理解。温度 31/29 时，执行器分别生成 PWM 75/0。必须把此能力表述为“模型编译＋执行器的传感器闭环”，不能声称未微调模型独立完成了数值比较。

验证先于任何动作收集，包括未选择的分支。程序限制为每级最多 8 节点、嵌套深度最多 2、总节点最多 32、最终动作最多 8。布尔、小数、字符串动作值不接受。模型输出只允许完整 JSON，禁止提取局部 JSON、补字段、自动修复或静默截断。

状态是同步有效的桌面快照：温度 -40–125、光照 0–100000，均有限；不是物理传感器实测。陈旧状态、接口驱动和实物功能仍由 T20/T26 验收。没有增加板卡/PDS 前置条件。

## 独立数据和冻结纪律

`tests/application/v2/` 包含单独的 2048 条训练数据、50 条开发数据和 200 条保留数据。训练更新只读 train；检查点选择只使用 dev。保留集在训练前固定，正式模型输出在发布配置冻结后才生成。旧保留集不作为训练或检查点选择数据。

三份数据使用不同完整指令和措辞族，并共享公开的设备、程序协议及操作语义。它们是有限人工模板及组合，不能声称是实际用户请求分布。条件样例同时覆盖成立/不成立及相等边界；保留集保留原有六类及 160 合法/40 非法分母，没有删除条件、非法设备或越界任务。

训练器采用官方 base、固定 seed、FP32、LoRA rank/alpha/目标层/学习率和梯度累积设置，配置与训练数据均保存 SHA-256。所有候选开发结果、损失记录、适配器文件与合并后的模型身份保留。原始权重在新协议上的失败对照也保留；不能只展示最佳检查点。

## 验收标准

合法任务必须同时满足：模型生成的完整程序与标签相同、执行器动作顺序/参数/查询对象和读数完全正确、由 EOS 停止。这样不会把错误条件在单个状态下偶然得到正确动作算通过。非法任务必须返回正确拒绝类型，且无动作和读数；格式失败不得算作正确拒绝。

合法成功率仍须 ≥90%，正确拒绝率仍须 ≥95%；另要求所有保留集传感器成对样例均通过，比旧协议的存在性检查更严格。阈值在第一次 v2 推理和训练前已写入配置。

发布评测保存完整 prompt、所有 token ID、生成长度与停止原因、模型程序、执行结果和逐条评分。模型须在独立网络命名空间中从本地 FP32 文件加载；分词、模板、UTF-8 和新进程重复生成要可核对。所有检查通过后才把 T02 从 BLOCKED 改为 DONE，并向 T05 交接实际使用的合并模型，而非旧 base。

## 下游变更

T05/T07/T10 使用发布锁指向的合并权重，tokenizer 和网络结构保持与 base 一致。T20 接收程序协议和执行器语义，负责实现对应的固件解析、状态新鲜度、执行和日志。T26 接物理传感器。该接口变更属于 T02 技术方案修订，不能据此标记 T00 的赛事规则、T20 固件或板级任务已完成。

### 导出后重新加载的兼容性固定

发布运行显式传入 `use_model_defaults=False`，保存并检查完整 resolved generation config；固定 greedy、beam=1、repetition_penalty=1、max_new_tokens=128。Transformers 4.57.6 对导出后的新版本 generation_config 会自动回填模型默认值，因此仅设置 `do_sample=False` 不足以固定策略。训练内的原始 4.37.0 配置未触发该回填。发布仍读取原始 SHA256 锁定的 Qwen tokenizer，权重读取合并后的适配模型。训练证据保持原样，兼容性修正记录在发布模型锁中，并要求全新开发集验证。
