# 2026 紫光同创选题一：v4 修复与继承的 v3 增强

本复核依据随包 2026 选题指南中选题一印刷页 8–9，以及本次实际源码和测试。指南未给出固定分项权重，因此这里说明对应要求与完成程度，不预测增加多少分。机器可读映射见 [competition-topic1-evidence-map.json](competition-topic1-evidence-map.json)。v2 原复核保存在包根目录 `topic1_v2_parent_export/docs/`。

## v4 正确性修复

v3 默认短 PV 路径仍可提出跨 4 KiB 的输出 DMA，生产第二组 Y=0xAC00AF00 是确定性触发地址。v4 统一 P/Y 页内分段，并修复短 V 合法 16 B 对齐地址的跨页读取；保留原范围检查、DMA 拒绝规则、完成身份、排空和浮点运算。默认与增强配置都包含修复。实际 CE 前后回放及 PV 边界/错误路径记录见包根 `verification/v4/`，完整说明见 `PV_DMA_PAGE_FIX.md`。

下文 CPU/CoreMark、软件和服务数据继承自 v3，未声称重新取得物理板成绩。普通文字首 Q 的现场根因仍为 OPEN，通用 FP 输出背压仍未解决。新位流的 PDS、真实模型 W 和普通文字上板回归仍待完成。

## 性能结论的边界

实际 CPU + 生产 SRAM RTL 的组合短测中，同一优化 CoreMark 二进制、同一外部行为 DDR 条件下，原 CPU/旧 SRAM 到 LRU+BTB/流水 SRAM 的性能种子周期为 6,492,864 → 4,878,643；校验种子为 6,513,449 → 4,889,417，均通过 CRC。这是组合运行的直接测量。它没有覆盖真实 PHY、布局布线、外部板级约束或正式运行时长，因此不能直接填成比赛 CoreMark/MHz、最高 Fmax 或 CoreMark/LUT。

单独 LRU 对当前 CoreMark 的收益很小，约 0.06%；对特定 Cache 冲突模式的改善较明显。BTB 和 SRAM 是这组短测主要的周期收益来源。软件数值计算维持既有严格 FP32 约束，不启用 fast-math，也不改动 CoreMark 算法、CRC 或计时口径。

## 后续最有价值的比赛证据

1. **对当前增强源码重新做 PDS。** 原历史 125 MHz 闭合结果及 LUT 只能说明原候选。记录新 CPU、完整 SoC、调试探针各自资源和实际时序；最高可用频率必须实测验证。
2. **同一位流、同一编译身份完成双种子正式 CoreMark。** 使用实际达到不少于 10 秒的迭代次数、官方 CRC 和完整 UART。分开填写 CPU 与完整 SoC 的 LUT 分母。
3. **完整模型对照与固定用例采集。** 使用真正模型/分词器资产，核对 KV、logits、生成 IDs 和错误路径；再跑固定 24 例公开开发诊断。新批采集工具逐请求保留原始字节，失败、缺失和超时仍在完整分母内；测试 fixture 不能算模型识别率。
4. **补真实 ILA。** 使用现有退休、stall、分支与总线探针，结合原子 PMU，记录 CoreMark 关键算法和推理阶段的触发窗口。离线 RTL 波形与 PMU 单元测试不是板端 ILA。

## 原先独立的功能缺口仍需如实说明

完整异常/中断尚未由本次性能增强补齐：历史与重建的 CPU 路线保留原接口语义，BRESP 写异常传播仍有缺口；生产启动关中断，trap handler 停止，软件 IRQ 仍为零。当前有异常/IRQ 端口和历史定向测试，不等于已经具备生产板端可恢复 ISR。处理这项需要定义 timer 清除、加速器完成和上下文恢复语义后再实现，不能直接打开全局中断。

AI 服务和主机网页展示已经具备，但物理传感器、FPGA 原生显示或执行器闭环仍未接入当前生产路径。既有 T20 虚拟 I²C/GPIO/PWM 与语义执行器的结果不能当作真实物理动作。实际设备型号、供电、引脚、采样单位与时效未落实前，不能给它们填写通过。

取消属于协作式执行：UART 收到携带 session 的取消命令后，在完整 block/token 边界停止发布、撤销前缀并恢复。当前 DMA 不在半写状态中强制切断。PMU 的 REQUEST 计数窗口也有明确起止边界；最终文档应同时保留算子计时、推理 PMU 窗口、首 token 与主机收字延迟各自的口径。

## 本轮新增验证限制

通用 FP 输出背压的独立 RTL 门仍失败，需继续定位并在合格 HDL 环境复核。当前 CE 组件通过只覆盖分元素 FF 仿真表示下的 M1/M4 K/V、长 PV、随机 DDR 停顿，外部 guard/adapter 状态为固定测试输入；不代表完整 SoC、物理 DDR、真实生产模型或任意 FP 消费模式。原 packed 独立 MUL 固定 ready 通过，历史 raw 完整 CE 负例仍未闭合根因。详见 `tests/competition_memory/README.md` 和包根 `verification/v3/memory/`，这些门不能被材料中的“已实现”替代。
