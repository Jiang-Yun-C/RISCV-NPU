# T15 W8 linear component contract v1

Producer T15; consumers T16/T19. Numeric `w8a8-g64-fp32-v1` and T05 thresholds remain unchanged. Physical weights/scales/bias consume T10 layout 0x1001 at their published SoC addresses; lm_head keeps the embedding alias.

The Coral program accepts one 96-byte request, ABI `0x4c4e3135`, and returns a 104-byte result. It uses the field containers in stream.h, with LINEAR opcode 2. source=Wq, scales=Sw, bias=optional FP32 bias, aq/sa=prequantized inputs, destination=Y, output_stride=global output row stride. session/sequence bind completion to submission. COPY fields and reserved[1..3] must be zero.

The private component supports M=1..512, N=1..151936, K=1..4864. Aq/Wq rows contain ceil(K/64)*64 bytes with zero padding; Sw/Sa contain ceil(K/64) FP32 scales. The frozen public API retains K={896,4864}, tight contiguous views and 16B starting alignment. Unsupported public tails/strides return explicit errors; the private K=65/127 and output stride adapters have separate component tests.

One operator submission autonomously runs M4 staging tiles and N128 blocks. Every row executes all groups; each group dot is signed INT8→INT32, then Coral scalar FP32 multiplies first Sa, then Sw, and accumulates groups in increasing order. Optional bias is added once. M=8 rereads weights for each M4 tile; this traffic is measured. There is no CPU per-group submission or scaling.

The optional reserved[0] audit pointer is a qualification feature. It writes INT32 dot and three FP32 values (activation product, scaled product, partial sum), ordered [M4 tile,N,G,tile M]. Production sets it to zero and returns only final FP32 Y. Audit traffic and cycles remain in totals. Input/weight/scale numeric errors return -9 with output_valid=0; accepted bus errors invalidate partial results, and the harness isolates and drains before reset.

result.compute_cycles measures weight load plus RVV dot execution. result.load_cycles measures activation and scale/bias transfer. checksum/reserved hold low/high halves of restoration_cycles, which are included in other_cycles; validation/control is other_cycles minus restoration_cycles. write_cycles includes all output and optional audit stores. These disjoint phases sum to result.cycles. AXI byte/wait counters are independently reconstructed from actual handshakes. Upload/native polling and simulator wall time are reported separately; 100MHz is a benchmark assumption, not board qualification.

The full directional dataset covers every one of 151936 vocabulary rows using disjoint simulator partitions. Each partition submits all K/groups as one operator. The coverage checker rejects missing/overlapping row ranges and retains all logits. Partitioning is a verification execution choice: the production API sends an unsliced N-row operator once; a single uninterrupted 151936-row hardware transaction and VexRiscv/native transport installation remain for T16 integration validation. M4/M8 head cases exercise first, middle and last ranges; the full vocabulary directional run uses M1.

linear_api.c implements the shared nx_linear_run provider for CPU_C and CORAL_RVV, with input quantization, tensor/span/numeric validation and timing. Binding a Coral provider requires a platform transport callback; T15 component submission is cocotb through the actual native slave. nx_query_caps remains mask=0 on the original unbound T13 context. Runtime nonlinear operations retain the T11/T12 CPU path and measured fallback trace; T15 installs no attention/vector acceleration. T16 qualifies actual CPU control, ownership and recovery with this numerical program.
