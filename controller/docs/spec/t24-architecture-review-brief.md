# T24 架构深度定制任务书（供 Pro 评审）

2026-10-13，用户提出：评估去掉 Coral 内部标量 RISC-V、把主计算融进主 CPU，并允许考虑异构多核；希望 Pro 做架构规划和深度定制。本文件扩大的是**方案研究范围**。当前 RTL、固件、ISA、黄金、正式验收状态及板端镜像未据此改变。

## 请解决的核心问题

在标准 MES2L676-200HP V1.2 / PG2L200H FBB676 -6 上，为现有 RISCV+NPU 项目设计可实现、可验证的计算架构。目标是关掉真实整板面积阻塞，并维持现有模型与数值/错误语义。不要只提出优化综合参数，也不要预先把架构限定为保留完整 Coral。

输出须同时考虑：主 CPU 的控制和现有 CPU 算子、W8A8 g64 INT32 点积、逐组 FP32 恢复、共享 DDR、TCM/局部 SRAM、错误恢复与 Cache 可见性。T24 的近期目标仍是同 T16 的最小软硬件链；完整模型与后续应用扩展单独列出，不冒充已纳入 T24 的实板成绩。

## 实测事实和面积边界

目标预算：159800 LUT6、319600 FF、415 DRM36K、740 APM。PDS2024.2/build178169。冻结整核（不含完整 DDR PHY/板级外围）335168 LUT、69493 FF、0 latch、27 DRM36K、418 APM，预算 FAIL。

- RVV backend：174979 LUT，**它单独就比器件 LUT 总容量多15179**。
- SCore：147442 LUT，其中 LsuV3 为110691 LUT、LsuSuperSlot为107926 LUT。该LSU同时接向量索引、向量数据、mask和向量load返回，不能算作完全可删的标量CPU。
- SCore扣除LsuV3后的账面余项是36751 LUT，包含仍可能需要的CSR、浮点、寄存器、取指、调度、退休和错误逻辑；没有证明这些全部可删。
- 假设整块SCore及LSU都被物理移除、且完全不计替代接口，旧层次账面其余仍为187726 LUT，超过容量27926；该假设本身会破坏当前向量访存链。
- 上述减法只用于说明旧网表的构成，不预测新架构面积，不代替实际映射。新CPU扩展、访存、缓存、仲裁、状态与错误处理都必须计入。

所有包含子层的行禁止相加。原始SNR、带父路径的层次CSV/JSON、独立实验收据均随包提供。

## 当前软件和硬件职责

主CPU是T09硬浮点VexRiscv，承担驱动、输入量化、所有权/会话管理和已有CPU算子；CPU生成器当前没有RVV插件。Coral内部SCore运行独立Coral ELF，负责循环、地址生成、描述符/数值校验、点积周边控制和标量FP32恢复，并为RVV提供指令、标量操作数、CSR及退休/异常协同。

当前链不是“主CPU发送点积指令给裸乘法器”：主CPU上传并读回Coral ITCM/初始化DTCM，写96字节request，启动真实Coral，待fault-free、guard drain、完整104字节result和匹配session/sequence后发布结果。错误/timeout后隔离、保留所有权、排空在途读写，再复位和重新上传。移除SCore时必须安排这些功能的去向。

精确源码定位及SCore子模块账本见随包的 `SCore_裁剪与主CPU融合.md`。当前`instructionLanes=4`是上游代码中的固定值，不能假设只改成1就得到可工作的完整窄发射设计。

## 至少比较五条路线

| 路线 | 需要研究的具体内容 | 兼容性问题 |
| --- | --- | --- |
| A 保留Coral、重构为更小的标量/向量结构 | 窄发射、少旁路、小ROB/队列、分时LSU/执行单元、银行RAM；保留完整既有ISA语义 | 能否保持原ELF/主CPU驱动？延迟是否触及原timeout？ |
| B 单CPU融合，主CPU直接驱动向量协处理器 | 给VexRiscv增加RVV或明确自定义接口；复用标量/FPU/地址控制，重构vector dispatch/VRF/LSU/退休 | 主CPU指令支持、CSR、精确异常、中断、阻塞/异步提交；原Coral ELF如何迁移？ |
| C 主CPU加命令式定制计算引擎 | 真实W8A8 g64点积、可选逐组FP32恢复；描述符队列、DMA/局部buffer、尾组mask、真实校验与恢复 | 属于新的内部执行接口；说明保留哪些API、修改哪些固件及后端能力声明 |
| D 主CPU加轻量控制核和共享向量/点积引擎 | 一个小顺序控制核替代宽SCore，保留独立执行/任务隔离；避免重复大FPU、LSU和旁路 | 不是把另一份完整Coral复制进来；解释共享执行资源与错误归属 |
| E 异构多核 | 控制/系统核、FP32/模型算子核、向量/点积核等合理划分；可仅两核，核数需有预算依据 | 核间协议、cache策略、DDR竞争、同步/任务切分/中断与复位；硬件重复及通信成本 |

异构多核不要求增加通用核数量。当前系统已经有主CPU与Coral标量核；新方案应明确解决哪些重复硬件或瓶颈。请给出适合本器件的最小核心组合，不能用“多核更快”作收益论据。

纯主CPU软件计算可以作为性能和成本对照，但若用它替代硬件加速链，必须声明验收范围变化，不能将CPU/F01回退当作原Coral硬件路径通过。

## 必须保留或明确迁移的语义

1. 冻结T05数值合同：W8A8、group64、INT32组内dot；逐组按 `FP32(FP32(dot)*Sa)`、再乘Sw、按组序累加、最后一次bias。量化整数、scale、dot逐位要求及FP32冻结容差都不改；禁止FMA/重关联、换格式、删行或改黄金。
2. 完整N151936、K896、单次不中断head；K4864、M1/M4/M8、N129尾组及各投影族也需要考虑。完整head不可拆调用替代；内部硬件tile可讨论，但不得改变一次提交的外部语义。
3. 输入和模型地址范围、只读权重保护、动态activation/weight/scale异常检测及原错误码；failure不得发布成功或复用半更新KV。
4. session/sequence、所有权、原子结果发布、lost/delayed IRQ、R/B错误、held-response timeout、排空及恢复；核间异常要有唯一归属和可观测记录。
5. CPU cache与DMA/加速器可见性。若多核无硬件一致性，要给uncached区/显式清理与失效/所有权协议，不能只写一个fence就假定DDR写已落地。
6. AXI128/256转换、byte mask、字节/四字节word地址、ID和返回顺序；HMIC用户口无B响应，其写完成另需资格。旧1024周期等待只在旧BIST镜像合格，8周期候选仍需独立实板资格。

允许Pro提出改变ISA、固件、Coral内部结构或执行后端的规划；每项须列出具体变更、数值/错误/软件影响及新增资格。这些建议还未执行，不算已有授权范围内的无差别替换。不要用旧固件成绩直接授予新架构资格。
